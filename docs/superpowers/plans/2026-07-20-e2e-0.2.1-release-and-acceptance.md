# E2E Runtime 0.2.1 发布与真实验收实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 发布修复 npm staging prefix 越界问题的 `0.2.1` 同版闭包，并从独立 Web 仓库的 PRD 完成真实 Chromium 验收、同代资产发布和报告审计。

**Architecture:** 七个 E2E 包保持精确同版闭包；安装器用 npm `--prefix` 固定事务 staging 目录。发布前先用本地 tarball 在空白 HOME 和带 Telemetry 父目录的 HOME 验证，公共 registry 发布成功后再用标准 `npm exec` 重装。业务验收只通过已安装 Runtime Host 的绝对 CLI、严格 JSON RPC 和仓库内中文 E2E Skill 编排。

**Tech Stack:** TypeScript、npm workspaces、Vitest、Playwright 1.61.1、系统 Google Chrome、E2E Runtime Host、GitHub、npm registry。

## Global Constraints

- 七个 E2E package 统一为 `0.2.1`，内部 `@mutil-skills/e2e-*` 依赖必须精确为 `0.2.1`。
- Playwright 与 `@playwright/test` 继续固定为 `1.61.1`。
- npm 安装必须显式绑定 transaction staging prefix，不能向 Telemetry Runtime 父目录安装。
- 真实浏览器使用系统 Chrome、一次性 Profile、Gateway 和 `local-confirmation`；不读取日常 Chrome Profile。
- 只有 Runtime Host 可计算 digest、状态、审批有效性、覆盖率、Verdict 和发布状态。
- raw evidence 只进入 Git 外 quarantine；项目内只允许 `.biztest` 同代脱敏资产。
- npm 凭证不可写入仓库、日志、计划或验收资产；公共发布缺少认证时继续完成本地发布闭包和业务验收，不伪造 registry 成功。
