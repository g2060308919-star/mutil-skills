调研最初推荐 Ember.js 示例，但该页面的业务 DOM 依赖多个脚本子资源。当前 Golden 的 Gateway 采用最小请求闭包，只授权冻结的主文档请求；为避免为了页面渲染放宽网络边界，本次选择同一官方规格下的 JavaScript ES5 示例。它的标题、h1 和初始态说明文案都直接存在于主 HTML 中。

## 验收范围

本次只验证 TodoMVC 初始页面的只读要求：

1. 页面标题为 TodoMVC: JavaScript Es5；
2. 主标题为 todos；
3. 页面可见文案包含 Double-click to edit a todo；
4. 不填写输入框，不点击控件，不写入 localStorage 或远端服务。

本次不能宣称已覆盖 TodoMVC 完整规格中的新增、编辑、删除、完成、过滤、路由和持久化，也不能宣称 Firefox/WebKit 跨浏览器兼容。

## 第三方页面适配边界

TodoMVC 原页面没有 Runtime 严格角色身份要求的 data-e2e-role。Golden 驱动只在发送给测试浏览器的 HTTP 响应中，为根元素增加 data-e2e-role="visitor"：

- 不修改上游网站或仓库源码；
- 不伪造页面标题、标题层级或业务文案；
- 不改变业务行为；
- Gateway 报告中的 injected=0，因为该角色适配发生在受控 fixture 响应层，而不是 Gateway 内容注入；
- 页面标题、h1 和断言文案仍直接来自上游 HTML。

长期应为第三方只读页面增加由规格定义的 URL + title + heading + oracle 身份策略，严格角色属性模式继续用于受控业务系统。

## Golden 与日常 Skill 流程的区别

本次是系统级 Golden：为了无人值守验证 Runtime 内部协议和全部资产链路，测试 Authority 使用受控的确定性审批身份。它验证的是审批绑定、签名 Grant、Gateway、浏览器执行、报告与发布回归实现能够贯通。

日常用户通过 E2E Skill 发起正式运行时，confirmation-required 仍必须由当前用户明确确认，Skill 或执行代理不能替用户确认。Golden 不能冒充用户的正式确认。
