## PRD 语义确认与追踪

Golden 在执行前生成并校验语义审查摘要，报告保留规范化 PRD 原文，并验证原文包含本次写入验收关键语义 `JSON Body`。

完整追踪路径为：

```text
PRD-ORDER-1
→ REQ-ORDER-1
→ RULE-ORDER-1
→ COV-ORDER-1
→ CASE-ORDER-1
→ ACTION-ORDER-1
→ EVIDENCE-ORDER-1
→ accepted
```

这条路径使使用者可以从 PRD 原文逐级确认 Requirement、Rule、覆盖义务、Case、浏览器 Action、Evidence 和最终 Oracle/Verdict，避免测试实现与 PRD 语义静默漂移。

## 安全与失败语义

验收同时覆盖以下 fail-closed 场景：

- 浏览器、Gateway 或 sanitizer 能力缺失时明确阻断，不伪造 accepted；
- target、payload、environment 或 PRD Revision 变化后旧 Grant 在浏览器动作前失效；
- 笼统批准不能签发生产或不可逆写入能力；
- 未授权请求不会触达上游；
- 写响应断连且副作用状态 unknown 时永久禁止自动重试，并发布 `safety-blocked` 事实；
- 并发发布通过 OS 锁和 fencing token 防止资产覆盖；
- 报告转义 XSS，并拒绝证据路径逃逸；
- cleanup 验证失败时不得发布 accepted。

验收过程中发现“写响应断连”Golden fixture 缺少 v2 严格审批契约要求的 `resourceKey`。已补齐为 `order:200`，单项回归 2/2 通过，随后完整发布级命令再次以退出码 0 通过。

## 验收边界

- 本次真实浏览器为系统 Google Chrome，不能据此宣称 Firefox 或 WebKit 已完成同等级真实验收。
- `local-confirmation` 默认允许当前 Skill 使用者批准测试，不验证组织身份，也不提供职责分离或组织级不可抵赖；报告明确记录 `identityVerified=false`、`separationOfDutiesVerified=false`。
- 本次使用本地受控 fixture 验证写入与 cleanup，不向第三方生产系统写入数据。
- 结论证明 0.3.0 的安装、执行、安全闭环与报告链路可用，不等于任意业务 PRD 都天然具备 100% 可自动化 Oracle；无法自动判定的义务仍必须明确标记为人工或 N/A 并完成审批。
