## Registry Golden 实际路径

`npm run verify:e2e-release` 实际执行以下链路：

1. 校验工作区干净，且本地与远端 `v0.8.0` 均精确指向当前发布提交。
2. 清理并重新构建全部 TypeScript workspace。
3. 打包 14 个 workspace，验证空白项目中的 package closure 和元数据。
4. 在全新临时 HOME 与空白用户项目中，从公共 Registry 精确安装 14 个 `0.8.0` 包。
5. 校验 Registry tarball、lockfile integrity、包版本和内部依赖版本。
6. 安装 Runtime，并移除用户项目中的安装输入，证明运行不依赖仓库源码路径。
7. 执行 Runtime doctor，验证系统 Chrome、Gateway 和正式 RPC 环境。
8. 运行 PRD 语义、测试设计、表单输入、Popup、多页面、JSON Body 写请求、证据、Cleanup、Reload 和最终报告链路。
9. 要求业务结果 accepted、发布 Golden 零失败零跳过，并清理 Runtime 自有临时目录和一次性浏览器 Profile。

## 0.8.0 能力验证范围

- Browser Executor Protocol 为 Probe、Preflight、Read、Reversible Write、Injection 与 Full Playwright 的生产默认路由；`legacy` 仅作为显式回滚，`shadow` 仅作为等价性诊断。
- `resolve-runtime --offline` 与精确 `--pinned` 策略进入 `prepare-input` 和 `create-run`，在安装锁内重新解析并原子冻结 Runtime closure。
- 已有 Run 只按冻结的 installation digest 恢复，不随 current 或 stable 指针漂移。
- Scheduler、Authority、Gateway、Browser、Cleanup 与 Reload 的真实调用链由 B2B 场景证明逐项绑定。
- 协议适配层保留执行器已持久化的截图、DOM、URL 和 Playwright Trace 引用，不重建或替换证据身份。
- 需求语义确认继续展示 `PRD 原文 → Clause → Requirement → Rule → Oracle → Case`，且在可信浏览器执行前完成确认。

## 明确边界

- Registry Golden 验证的是已发布 0.8.0 的安装、系统 Chrome 与正式 E2E 执行闭环，不等同于稳定自托管性能 Runner 已上线。
- 验收时仓库登记的 self-hosted Runner 数量为 `0`，Actions 中生产 TUF 变量数量为 `0`。因此独立的 `E2E B2B Coverage` / operational workflow 尚不能产生 `gateEligible=true` 的稳定宿主证明；不得用普通开发机或测试 TUF origin 伪造该结论。
- 生产 stable Runtime 更新仍要求真实离线密钥、经审查的 bootstrap root、受控 HTTPS metadata/target origin、密钥轮换与撤销演练；条件缺失时 `stable` 继续 fail-closed，`offline` 与精确 `pinned` 可正常使用。
- 本次真实浏览器为系统 Google Chrome，不据此宣称 Firefox 或 WebKit 已完成同等级真实验收。
- 任意业务 PRD 是否能 100% 自动判定仍取决于业务 Oracle 与测试数据可用性；无法自动化的义务必须显式标记为人工或 N/A，不能静默遗漏。

E2E Skill / Runtime 0.8.0 已达到正式 npm 发布门禁：版本真相统一、十四个发布包公开可安装、OIDC 发布成功、安装后跨仓 Golden 零跳过、系统 Chrome 全链路可执行、报告与浏览器证据可追踪，发布结论为 **accepted**。
