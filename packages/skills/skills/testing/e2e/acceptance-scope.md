# 验收范围确认

## 目的

将 PRD 与用户诉求收敛为本轮验收边界，并完成唯一的首次用户确认。

## 触发条件

当已具备 PRD 且需要确认测什么、不测什么、歧义如何处理时使用。

## 必需输入

已确认的 PRD manifest、规范化 PRD 和用户原始验收诉求。

## 可选输入

设计稿或交互规范引用、URL、账号、环境、历史 acceptance scope。

## 独立调用守则

独立调用时，缺少任一上述命名输入，明确列出缺失的文件或信息并请求用户提供；返回 blocked，不得推断、重建、补写或执行任何上游阶段。

## 工作流

提取候选需求，映射用户诉求，划分纳入和排除项，标记歧义与依赖，声明视觉范围，再集中请求确认。

## 详细算法

为每个纳入项分配或复用 REQ-ID，并保存 sourceRefs。区分需求、背景、埋点、灰度和明确不做项。列出 URL、账号、角色、数据、环境、设计与外部系统依赖。影响结论的歧义必须有用户答案，或被明确排除出确定性验收。

## 输出

acceptance-scope.json，含 includedRequirements、excludedRequirements、ambiguities、dependencies、visualScope 和 confirmation。

## 完成条件

confirmation 为 confirmed，决定人和时间存在，纳入 REQ 都有来源，歧义和视觉边界均已处理。

## 阻塞条件

PRD 不完整、用户诉求无法映射、影响结论的歧义未决，或首次确认尚未完成。

## 禁止行为

不得生成 Case、猜测歧义答案、把当前页面表现当作预期，或在未确认时继续浏览器执行。

## 独立使用示例

用户只要求列表筛选时，纳入对应 REQ，排除审核写操作并记录理由，再一次性请求对歧义和依赖的确认。
