# 预期交互流程

## 目的

将需求模型组织为用户入口、动作、决策、反馈和状态变化构成的预期流程。

## 触发条件

当需求模型已完成且需要设计预期用户交互流程和风险分类时使用。

## 必需输入

requirement-model.json 和 confirmed acceptance-scope.json。

## 可选输入

经确认的设计或交互规范。

## 独立调用守则

独立调用时，缺少任一上述命名输入，明确列出缺失的文件或信息并请求用户提供；返回 blocked，不得推断、重建、补写或执行任何上游阶段。

## 工作流

为每个 REQ 建立或声明无交互 FLOW，绘制主链、权限、校验、空态、错误、超时、恢复与终点。

## 详细算法

每个节点记录 nodeId、kind、actor、前置、期望 UI、期望 Network、关联 REQ/RULE、下一节点与 read-only、write 或 irreversible 风险。为成功和失败路径定义终点；把风险标注交给执行契约，而非在此绑定控件。

## 输出

interaction-flow.json 与可选 interaction-flow.mmd。

## 完成条件

每个 REQ 至少映射一个 FLOW 或有无交互说明，关键分支和风险均已显式表示。

## 阻塞条件

需求模型缺少可观察结果、角色、状态转换或关键错误预期。

## 禁止行为

不得选择 CSS Selector、探索真实页面、改变预期或隐瞒写和不可逆动作。

## 独立使用示例

筛选流程包含页面入口、选择城市、加载、列表更新、空态和请求失败恢复分支。
